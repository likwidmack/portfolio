# Interaction redesign (Likwidmack, September 2026)

A focused pass on how visitors and the site owner **use** the portfolio: readable contrast in both themes, no lost work, navigation that is always visible, no dead ends, simpler browsing and a safer Style Studio. The visual identity (warm near-black grounds, deep red, ember, clay, condensed display type) is unchanged.

- Design spec: superpowers/specs/2026-09-23-likwidmack-redesign-design.md
- Implementation plan: superpowers/plans/2026-09-23-likwidmack-redesign.md

## Rules that keep it this way

1. Text and controls use the contrast roles (brand-coloured text: `--theme-primary-ink-color` / `--theme-secondary-ink-color`); brand colours are for fills. Tests fail if a role drops below its minimum (`theme/core/tests/contrast-roles.spec.ts`).
2. One primary action per view; one link or button per object (card, door, asset).
3. Every story or result list offers a next step (pager, Clear filters, Retry).
4. Changes that can be lost are kept until the person applies or discards them; destructive actions confirm in place and offer Undo.
5. Status is always a word (and often a glyph), never colour alone.

## Responsive regression (e2e)

Three Cypress specs guard the responsive · accessible · touch rule (`docs/agents/README.md`):

| Spec                                               | Scope                                                                                                 | Checks                                                                                                                                                         |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `core/web-e2e/src/e2e/responsive.cy.ts`            | `RESPONSIVE_ROUTES` at 320 / 768 / 1024 / 1440                                                        | Page-level horizontal overflow only.                                                                                                                           |
| `core/web-e2e/src/e2e/ui-audit.cy.ts`              | `PUBLIC_ROUTES` at 375 / 768 / 1280, 320px reflow, phone Menu sheet, page-nav disclosure              | Overflow, 44px targets, 12px type floor, accessible names.                                                                                                     |
| `core/web-e2e/src/e2e/responsive-components.cy.ts` | Every public route at 375×812, 768×1024 and 1024×768, 320×640 reflow on key pages, and the components | Overflow, clipped or spilling text, overlapping text, controls off-screen, media wider than its box, plus the ui-audit floors; components opened and measured. |

**Routes come from the source.** `core/web-e2e/src/support/routes.ts` globs `core/web/app/pages/**/*.vue` (static routes) and `core/web/content/case-studies/*.json` (`/work/<slug>`) with Vite's `import.meta.glob`, so a new page joins the matrix on its own. One doc page and one blog post are resolved at run time from `/docs` and `/api/posts`. An empty `/docs` index fails (docs ship with the repo), and so does a non-200 `/api/posts` (the store is missing: run `npm run db:migrate:local`). `npm run e2e:regression` seeds one published fixture post (`scripts/e2e-seed-posts.js`, test data only), so on CI (`Cypress.env('CI')`, set from `CI` in `cypress.config.ts`) an empty blog store fails too. Locally the blog test logs the reason and is marked pending with `this.skip()`; run `node scripts/e2e-seed-posts.js` after `db:migrate:local` to audit it.

**Components** (phone, tablet portrait, tablet landscape): the primary Menu sheet (Tab order, `Esc` closes and returns focus; inline nav from 48em), Personalize, Style Studio (scroll, controls, Apply / Discard bar), page-nav disclosure, gallery and code browse toolbars (pickers ≤ 768px, segments above), the work jump bar, the code snippet picker and `‹ ›` steps, media player controls, the story pager, footer social links and the evidence examples dialog. Each one is opened and checked: inside the viewport, scrolls inside when taller, 44px targets, named controls, no sideways scroll, and no control hidden at rest that only a `:hover` rule reveals.

**Shared audit.** `core/web-e2e/src/support/layout-audit.ts` holds `floorAudit` (the ui-audit floors), `layoutAudit`, `surfaceAudit` and the hydration-aware `visitHydrated`. `SCROLL_ALLOWLIST` there lists the intentional scroll containers (code frames, table wrappers, carousels) and the decorative layers.

**Known issues.** Real layout bugs found by the suite go in `KNOWN_ISSUES` at the top of the spec. Each entry names its issue and matches only its findings, so the suite stays green while the fix lands; remove the entry with the fix and the check guards the regression. The list is empty today: KI-1 and KI-3…KI-9 were fixed in one pass (see the TODO entry below).

**Cropped text and visible ink.** Clipping follows the _containing-block chain_. A box's `overflow` clip applies to a run only when the box sits on that chain. An `absolute` child escapes a non-positioned `overflow: hidden` wrapper; a `fixed` one escapes everything up to a transform, filter or contain ancestor.

- **Crop check.** A run whose visible ink is under 90% of its line boxes is reported under `clipped` as _crops text_, vertically as well as horizontally (a caption pushed out of a fixed-height frame). Scroll containers, `SCROLL_ALLOWLIST` (code frames, carousels) and ellipsis or line-clamp truncation are intended crops and are not reported.
- **Overlap check.** It compares the visible ink only. Hidden ink is either reported by the crop check or sits in one of those intended crops.
- **Sticky boxes.** Each run records its nearest `position: sticky` root. A pair is skipped only when the two runs have different roots and one root is _stuck_ at that moment, meaning it is offset from its static position. Pairs inside one sticky box (for example `header.site-chrome`) are always checked, and so is a sticky box sitting in flow.
- **Self-tests.** `core/web-e2e/src/e2e/layout-audit.cy.ts` covers both rules. One case rebuilds the pre-fix KI-8 gallery caption and checks that the audit catches it.

**Settle before measuring motion.** Media queries are re-evaluated in the browser's rendering step, not on a forced layout. Headless, after `cy.viewport` a page can keep the previous viewport's `(orientation)` state until something produces a frame — on /work that flips every card's `--media-ratio` (16:9 → 9:16) right after a jump. `settleLayout()` nudges scroll by 1px, dispatches `resize`, then waits two animation frames and three consecutive steady document-height samples before the jump-bar click. The jump itself is instant because `visitHydrated` seeds `motion: 'reduced'`, which the handler reads (setting `data-motion` on `<html>` alone does not change it). Settling still missed once on 768×1024 (story left at top ~4200), so if the story is off screen and the document height changed after the click, the test jumps once more; a jump link that never scrolls still fails, and the record notes `rejumped`.

**Output.** Raw measurements are written to `core/web-e2e/test-output/responsive/<viewport>/{pages,components}/*.json`. Screenshots go to `core/web-e2e/test-output/cypress/screenshots/responsive-components.cy.ts/<viewport>/{pages,components}/` (full page per route, plus each open component at phone and tablet portrait). Both folders are gitignored.
